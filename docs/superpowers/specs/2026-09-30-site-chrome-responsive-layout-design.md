# YOYANT 公共头尾与全站响应式规范设计

## 目标

重构 YOYANT 主站的公共头部与底部，使中英文页面具有一致、简洁、国际化的品牌框架；同时建立可重复执行的全站布局审计，修复所有公开页面在常见视口中的导航折行、控件拥挤、元素重叠和横向溢出。

仓库仍保持纯静态部署：提交后的 HTML 必须包含完整可索引标记，不依赖客户端 JavaScript 才能出现导航和底部。

## 范围

### 接入 YOYANT 公共头尾

- 中文与英文首页。
- 中文与英文 About 页面。
- 中文与英文 Services 页面。
- 中文与英文 Resources 列表及文章页面。
- 中文与英文 YOYANT 案例说明页。

### 保留独立品牌外壳

`work/*` 和 `en/work/*` 中作为完整客户站或概念站呈现的独立 demo，继续使用各自的品牌、导航和底部。它们不接入 YOYANT 公共头尾，但必须通过相同的响应式布局审计，并修复异常换行或溢出。

### 全仓扫描

审计覆盖仓库内全部 HTML，包括 `404.html` 和预览页面。明确被标记为内部文件的页面仍接受本地布局检查，但不改变其索引策略。

## 品牌与视觉系统

YOYANT 公共头部采用紧凑的国际化工作室品牌锁定组合：

```text
YOYANT.
DIGITAL PRODUCT STUDIO
```

中文副标为 `设计与软件工作室`。品牌规则如下：

- `YOYANT.` 使用清晰的几何粗体，蓝色句点是唯一的品牌强调色。
- 副标使用小号中等字重和克制字距，紧贴主标，不再罗列业务清单。
- 品牌、导航和工具区共享同一网格和垂直中心。
- 桌面头部高度约 72px，移动端约 60px。
- 公共导航使用简短命名：中文为 `服务 / 案例 / 工作室 / 洞察`，英文为 `Services / Work / Studio / Insights`。
- 主行动按钮为中文 `开始合作 ↗`、英文 `Start a project ↗`。
- 语言与主题控制组成紧凑工具区，不与主导航争夺主视觉。
- Footer 复用相同字标、颜色、间距和网格，形成一致的首尾框架。

## 静态公共组件架构

公共头尾采用“模板源文件 + 同步脚本 + 完整静态输出”，而不是运行时注入。

### 模板

- `scripts/templates/site-header-zh.html`
- `scripts/templates/site-header-en.html`
- `scripts/templates/site-footer-zh.html`
- `scripts/templates/site-footer-en.html`

模板目录已被 `_redirects` 的 `/scripts/*` 规则挡在公开站点之外。

### 页面标记

接入公共组件的页面使用稳定注释边界：

```html
<!-- SITE-HEADER:START -->
<!-- SITE-HEADER:END -->

<!-- SITE-FOOTER:START -->
<!-- SITE-FOOTER:END -->
```

页面中仍保留同步后的完整 HTML。搜索引擎、无 JavaScript 环境和 GitHub Pages 均能直接读取结构。

### 同步器

`scripts/sync_site_chrome.py` 负责：

- 根据页面语言选择中英文模板。
- 根据页面路径设置导航当前项和链接根路径。
- 替换标记之间的内容，保持标记外内容不变。
- 支持写入模式和 `--check` 只读校验模式。
- 保证重复执行结果不变。
- 遇到缺失标记、重复标记、未知语言或无法分类的公共页面时失败并列出路径。

### 公共样式与交互

- `assets/site-chrome.css` 保存公共头尾视觉与响应式规则。
- `assets/nav-menu.js` 只处理菜单开关、焦点、Escape 关闭和滚动锁定等交互，不再内嵌重复视觉 CSS。
- 页面必须显式引用公共 CSS 和交互脚本。
- 当前页状态通过同步后的语义类名和 `aria-current="page"` 表达。

## 响应式与换行规范

### 不允许异常折行的界面元素

- 桌面主导航链接。
- 按钮、语言切换、主题切换和短标签。
- 面包屑的单个路径片段。
- 数字、价格、日期、单位和短状态文本。
- 品牌主标和副标内部。

这些元素默认使用 `white-space: nowrap`。当空间不足时，导航必须先折叠为菜单，而不是压缩字体、缩短间距直至拥挤，或允许单个导航项变成两行。

### 允许自然换行的内容

- 正文、引言、列表和长说明。
- 页面标题、文章标题和卡片标题。

允许换行不代表允许溢出。标题需使用适合中英文的最大宽度、字号和行高，避免可合理消除的单字或单词孤行。中文宽度使用 `em`，不使用为拉丁字符设计的 `ch` 来估算每行中文字数。

### 断点策略

- 断点由实际内容所需宽度决定，中英文可不同。
- 在导航第一次发生折行、碰撞或侵占工具区之前切换到移动菜单。
- 各独立 demo 按自己的内容和导航家族设置断点，不强制统一成 YOYANT 视觉。
- Footer 在窄屏改为单列或合理分组，不允许链接和版权文字互相挤压。

## 自动化布局审计

新增 `scripts/audit_layout.py`，通过本机无头 Chrome 加载本地静态站，扫描全部 HTML 页面。

### 视口矩阵

- 桌面：1440、1280、1100、1024、900px。
- 平板与移动端：768、430、390、360px。

### 自动检测

- 页面根节点出现横向滚动。
- 导航链接、按钮、工具控件或品牌标识出现多行。
- 同一导航区域的可见元素发生矩形碰撞。
- 可见内容超出视口或所属容器。
- 公共头尾缺失、标记不完整或模板未同步。
- 页面加载脚本产生控制台错误。

允许换行的正文和标题不作为通用失败条件；对标题只报告明显孤行供人工复核，避免自动修改正常排版。

审计结果按页面、视口和问题类型输出。命令以非零状态结束时不得提交或部署。

## 开发规则文档

新增 `docs/frontend-rules.md`，覆盖：

- 新页面必须选择公共 YOYANT 外壳或明确的独立 demo 外壳。
- 公共头尾只能修改模板，不得直接在单页永久修改同步区域。
- 公共组件修改后必须运行同步器。
- 导航命名、当前项、语言和主题控制规范。
- 中英文排版、字号、行高、最大宽度和换行规范。
- 响应式断点决策原则。
- Footer 内容和移动布局规范。
- 图片继续遵守现有 `scripts/imgctl.py` 规则。
- 新增或删除页面后继续执行 Sitemap 生成与检查。
- 提交前必须执行公共组件同步检查和全站布局审计。

## 回归与人工验收

### 自动验收

1. 同步器测试先证明旧页面未接入或失同步时失败。
2. 同步后验证中英文模板、相对导航状态和幂等性。
3. 全站布局审计覆盖全部 HTML 和全部视口矩阵。
4. `python3 scripts/gen_sitemap.py --check` 必须通过。
5. 搜索临时调试标记和控制台诊断代码，结果必须为空。

### 人工抽查

- 中英文首页。
- 中英文资源列表和文章。
- 中英文服务页。
- 中英文 About。
- YOYANT 案例说明页。
- 每一种独立 demo 导航家族至少一个中英文代表页。
- 桌面、平板和手机各一个代表视口。

## 提交与部署

- 所有修改在本地完成并通过最新一次完整验证后提交。
- 提交前运行公共组件同步检查、布局审计和 Sitemap 检查。
- 推送 `main` 会直接部署 GitHub Pages 和 Cloudflare Pages，因此只推送已验证提交。
- 推送后检查 GitHub 远程状态，并访问线上中英文关键页面确认公共头尾、菜单和响应式行为。
- 若线上验证失败，停止继续修改范围，先定位部署差异或缓存问题。

## 非目标

- 不把独立 demo 改成 YOYANT 品牌。
- 不引入 React、Next.js 或新的站点生成器。
- 不重写页面正文或改变现有 SEO 索引策略。
- 不以缩小字体作为解决导航空间不足的主要手段。
