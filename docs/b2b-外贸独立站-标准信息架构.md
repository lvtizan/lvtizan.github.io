# B2B 外贸独立站 · 标准信息架构

> 用途：所有 B2B 外贸样板站与客户交付站照此搭建，不必每次重想结构。
> 适用范围：工厂 / 贸易商面向海外采购商的**询盘型**站点（≠ DTC 电商，两者结构完全不同）。
> 创建 2026-08-02。回写触发条件见 §10。

---

## 1. 先记住一个反直觉的结论

调研的一致结论是：**中国工厂外贸站的瓶颈不是流量，是访客到达后的信任转化失效**。典型工厂站转化率约 1%。

而低转化站和高转化站的结构差别，不在"页面够不够多"：

| 低转化 | 高转化 |
|---|---|
| 纯产品目录 | **技术应用指南** + **认证中心** |
| 密密麻麻的参数表格 | **行业场景化应用说明** |
| 散落各处的证书图片 | 集中、可下载、机器可读的合规中心 |

**所以做 B2B 样板站，重点不是把产品列全，是把「信任」和「场景」两件事做出来。** 这是与 DTC 电商最大的分野——DTC 靠视觉和价格驱动冲动决策，B2B 靠证据消除采购风险。

**一个高信号成本项**：约 67% 的欧洲采购经理把 `@qq.com` / `@gmail.com` 邮箱视为红色警告。企业域名邮箱是零成本的信任门槛，**样板站的联系方式必须演示企业域名邮箱**。

## 2. 标准页面结构（8 页）

一级导航控制在 **6–8 项**，超过就该收进二级。

| # | 页面 | 路径 | 作用 | 必须可点进 |
|---|---|---|---|---|
| 1 | 首页 | `/` | 30 秒内回答"你是谁、做什么、凭什么信你" | ✅ |
| 2 | 产品分类 | `/products/` | 按品类/材质/规格筛选，通往详情 | ✅ |
| 3 | 产品详情 | `/products/<slug>/` | 规格表 + 应用场景 + PDF + 询盘入口 | ✅ 至少 2 个 |
| 4 | 应用方案 | `/solutions/` | **按行业场景**组织，不按产品组织 | ✅ |
| 5 | 工厂实力 | `/factory/` | 产线、产能、质检、SOP | ✅ |
| 6 | 认证中心 | `/certifications/` | 集中、分类、可下载 | ✅ |
| 7 | 关于我们 | `/about/` | 沿革、团队、出口市场分布 | ✅ |
| 8 | 联系 / 询盘 | `/contact/` | 多渠道 + RFQ 表单 | ✅ |

可选加分项：`/blog/`（技术内容，SEO 主力）、`/faq/`、`/download/`（样本册/图纸打包）。

**样板站至少要做全 1–8，且每页都能点进去逛。** 只有能逐页翻的站才当得了销售工具——给土老板看的时候要能说"你点这里试试"。

## 3. 每页的必备模块

### 3.1 首页

按此顺序，**信任信号必须在首屏之后立刻出现**：

1. **Hero**：一句话说清「做什么产品 + 服务什么行业 + 主要出口市场」，配主 CTA（Get a Quote）
2. **信任条**：成立年份 · 厂房面积 · 年产能 · 出口国家数 · 主要认证 logo 一排
3. **产品品类入口**：4–6 个大类，配图 + 一句话，直通 `/products/`
4. **按行业的应用场景**：3–4 个行业卡片，直通 `/solutions/`
5. **工厂实景**：产线照片或**视频**（视频冲击力显著强于图片），直通 `/factory/`
6. **认证墙**：证书缩略图一排，直通 `/certifications/`
7. **合作客户/出口市场地图**（有就放，没有别编）
8. **底部 CTA + 完整联系方式**

### 3.2 产品分类页

- **筛选器**：按品类 / 材质 / 规格 / 型号，至少 3 个维度（研究明确指出要有 size / material / part number 过滤）
- 卡片含：主图 + 型号 + 2–3 个关键参数 + "Inquire" 按钮
- **每张卡片都要有独立询盘入口**，不要只在页面底部放一个表单

### 3.3 产品详情页（最关键的一页）

必须同时具备这四块，缺一不可：

1. **图组**：多角度实拍 + 细节图（走 `imgctl.py shot` 出灯箱高清源）
2. **规格表**：结构化参数，可横向滚动，移动端不能挤爆
3. **应用场景说明** ← **这是低转化站普遍缺的**。不要只堆参数，要写"这个型号用在什么工况、解决什么问题、配套什么设备"
4. **资料下载**：产品 PDF / 图纸 / 质检报告，**直接给下载，不要求先填表**（要求填表才能下载会大幅压低下载量，而下载本身就是高意向信号）
5. **就地询盘表单**：预填当前型号，不要让人跳到 `/contact/` 再重新描述

### 3.4 应用方案页

**按行业组织，不按产品组织。** 采购商的心智是"我做水处理，我需要什么"，不是"你有哪些型号"。

每个行业一块：行业痛点 → 推荐型号 → 选型建议 → 案例或参数对照 → CTA。

### 3.5 工厂实力页

- 产线照片/视频（**视频优先**）
- 产能数据：月产能、交期、MOQ
- 质检流程与 SOP 制度（有图更好）
- 设备清单
- 验厂报告（有则放）
- 团队与规模

### 3.6 认证中心（信任转化最直接的杠杆）

**必须分类展示**，不要一堆证书图片糊在一起：

| 分类 | 内容 |
|---|---|
| 进出口资质 | 营业执照、进出口经营权 |
| 企业体系认证 | ISO 9001 / ISO 14001 等 |
| 产品国际认证 | CE / FDA / RoHS / UL 等 |
| 质检报告 | SGS / BV / TÜV 等第三方报告 |
| 专利与商标 | |

每张证书要：**高清可放大查看 · 标注用途与适配市场 · 提供 PDF 下载**。

> ⚠️ **样板站的红线**：样板站**不得使用伪造的认证证书**。用明确标注的占位图（如"CERTIFICATE SAMPLE · 样板演示用"水印），或只画出版式与信息结构而不放具体证书内容。这条与仓库既有规则一致——不编造虚假客户名/评价/真实品牌 LOGO。**认证是采购决策依据，伪造的后果比假客户名严重得多。**

### 3.7 联系 / 询盘页

多渠道并列，不要只留一个表单：

- **企业域名邮箱**（`sales@domain.com`，**绝不能是 qq/gmail**）
- **WhatsApp**（外贸必备，研究明确点名）
- RFQ 表单
- 电话（含国家码）
- **工厂实际地址**（增加信任度，研究明确提及）
- 可选：视频会议预约

## 4. RFQ 询盘表单规范

**RFQ ≠ Contact form。** 通用联系表单只收"姓名邮箱留言"；RFQ 要收**足以让供应商直接报价**的信息。这是 B2B 站表单设计的核心区别。

### 字段设计

**第一屏（必填，控制在 5 个以内）**
| 字段 | 类型 | 备注 |
|---|---|---|
| Product / Model | 文本或下拉 | 从产品页跳来时**自动预填** |
| Quantity | 数字 + 单位 | 判断是否够 MOQ |
| Company Name | 文本 | 过滤个人询价 |
| Business Email | 邮箱 | 校验非免费邮箱可选 |
| Country / Market | 下拉 | 决定认证要求与物流方案 |

**第二屏（选填，可折叠或分步）**
- Target Price / Budget
- Required Certifications（多选：CE / FDA / RoHS…）
- Delivery Term（EXW / FOB / CIF）
- Expected Delivery Date
- Specifications / Drawings 上传
- WhatsApp / WeChat
- Message

### 实现要点

- **分步 + 进度指示**：长表单必须拆步骤，不要一屏 15 个格子
- **条件字段**：选了某品类才出现该品类特有的参数字段，保持简短相关
- **移动端优先**：63% 的 B2B 采购初次检索发生在移动端；表单、点击拨号、报价按钮都必须移动端可用
- **产品页就地提交**，不跳转

### 静态站怎么做表单（本仓库技术栈的实际卡点）

我们的站是纯静态、托管 CF Pages，**没有后端**。可选：

| 方案 | 说明 |
|---|---|
| **Cloudflare Pages Functions** ⭐ | 同平台、免费额度够、可转发邮件或写 KV。样板站首选 |
| Formspree / Web3Forms | 零代码，免费额度有限，适合样板演示 |
| 客户交付站 | 若客户要询盘入库 + 后台查看，则需真后端，属于**加价项**，报价要单独算 |

**样板站用前两种即可**，重点是演示交互流程，不需要真的落库。

## 5. 多语言

- **子目录方案**：`/`（英）+ `/es/` `/ru/` `/ar/` 等，**不要**用参数或 cookie 切换
- 每页 `<link rel="alternate" hreflang="xx" href="...">` 互指，并含 `x-default`
- 语言切换器放导航右上角，**显示语言名而非国旗**（国旗表示国家不表示语言）
- 阿语站需 `dir="rtl"`，布局要能镜像
- 样板站做 **英 + 1 个第二语言**演示即可，不必做全

## 6. Schema 结构化数据（低成本高回报）

调研中反复出现的一条：多数工厂站**零结构化数据**，这同时损失搜索富摘要和 AI 检索可见性。

必须加的 JSON-LD：

- **Organization**：含 `name` `logo` `address` `contactPoint` `sameAs`（指向已验证的平台主页，如阿里国际站/领英）
- **Product**：每个产品详情页，含 `name` `image` `description` `sku` `brand`
- **FAQPage**：FAQ 区块
- **BreadcrumbList**：分类导航

> 这块与站内既有做法一致，可参考 `/resources/structured-data-json-ld/` 那篇文章。

## 7. 本仓库落地约束

搭 B2B 样板站时同时遵守既有铁律（详见根目录 `CLAUDE.md`）：

- **图片一律走 `scripts/imgctl.py`**：封面/hero 用 `cover`（出 srcset 两档），产品细节图用 `shot`（出灯箱高清源）
- **新增页面后跑 `python3 scripts/gen_sitemap.py`**；`.githooks/pre-push` 会拦截漏更新
- 要排除某页被索引，给它加 `<meta name="robots" content="noindex">`，**不要手改 sitemap**
- 导航当前项要有选中态
- **样板站必须标注样板身份，禁用真实品牌 LOGO、真域名、虚构客户评价、伪造认证**
- 文案能一行放下就不要两行

## 8. 首个样板站的落地建议

**行业选五金/机械**（东莞、佛山密度最高，需求最标准，最易被搜到）。

页面清单按 §2 全做，其中：
- 产品详情页至少做 2 个（一个标准件、一个定制件，演示两种询盘路径）
- 应用方案页至少 3 个行业场景
- 认证中心用标注水印的占位证书
- 表单用 CF Pages Functions 演示完整提交流程

**锚一个长尾词**（与 `TODO.md` 的关键词分工表对齐，禁止与既有页面互相竞争）。

## 9. 与 DTC 电商样板的分工

站内已有 `aveline` / `reson` / `yunshang` 三个**可体验的 DTC 电商样板**（含购物车、结账、账户）。本文档覆盖的是**另一条线**：

| | DTC 电商样板 | B2B 询盘样板 |
|---|---|---|
| 核心动作 | 加购结账 | **提交 RFQ** |
| 信任来源 | 用户评价、退换政策 | **认证、验厂、产能** |
| 内容组织 | 按商品 | **按行业场景** |
| 客户画像 | 品牌方 / 跨境卖家 | **工厂 / 贸易商** ← 主推客群 |

两条线都要有，因为来问的老板两类都有；但**B2B 是主推方向，优先补齐**。

## 10. 回写触发条件

以下情况必须更新本文档：

- 新做一个 B2B 样板站，发现了本文档没覆盖的模块或坑
- 客户实际询盘反馈显示某个字段/模块无效或缺失
- 表单实现方案变更（如从 Formspree 换到 CF Functions）
- 多语言或 Schema 方案调整

纯设计换肤、纯文案微调不必回写。
