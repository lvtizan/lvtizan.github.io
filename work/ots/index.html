项目问题 · The Brief

国际工程采购并不只是在找一台电梯。客户要在短时间内判断：项目能否覆盖目标市场、技术方案由谁配合、制造与发运怎样衔接、安装调试及后续服务如何落地。若官网只堆产品图或公司介绍，这条判断链路会被打断。

OTS 的官网因此不按“品牌故事 → 产品列表”的常见顺序展开，而是先建立项目交付能力的整体认知，再通过全球网络、制造基地、现场运营、项目参考和项目询盘逐层回答工程采购方真正关心的问题。

Information strategy · 信息策略

先证明“能交付”，再讨论“卖什么”

OTS 不把首页做成产品目录。页面以采购方的风险判断顺序组织，让每一次向下滚动都回答一个更具体的工程问题。

01 / CAPABILITY

先建立规模与边界

首屏不谈单一型号，用“全球研发、中国制造、国际交付、全周期服务”定义能力范围。随后用数字、网络与制造基地把抽象承诺落到可验证的信息。

02 / EXECUTION

把安装变成可见流程

安装并非页面末尾的一项服务。它被拆成现场团队、标准化节点、质量控制与安全前提，并与制造、物流、调试串成连续的项目链路。

03 / EVIDENCE

用相似项目降低决策成本

项目参考按机场、轨道交通和公共建筑分类，卡片同时保留国家、项目名与设备数量。访客能迅速判断是否做过与自己相近的复杂场景。

Making process · 制作过程

不是先画页面，而是先把采购方的判断顺序理清

从项目方真正需要确认的信息开始，把复杂业务翻译成清晰、可信且能促成询盘的官网结构。

01 / DISCOVER

拆解工程决策

从项目地点、建筑类型、井道与技术参数，到发运、安装和维保，把买家决策中的关键问题列为页面骨架。

02 / STRUCTURE

重组可信信息

把全球网络、制造与设计中心、现场运营和项目资料各归其位，清楚标识服务承诺与项目参考的边界。

03 / DESIGN

克制的工程感

以深蓝、骨白与高对比信息层级构建“Quiet Engineering”视觉语言，让大型项目的秩序感成为页面气质。

04 / SHIP

让内容被找到

把页面可见内容同步写入结构化数据、站点地图与分享卡片；表单、可访问性和图片加载则服务于真实转化。

Interface walkthrough · 界面逐屏拆解

把官网的关键界面放大讲透

每一个大幅页面都服务于一个明确的客户问题：我是否可信、能否落地、是否做过相似项目、下一步怎样开始。

01 / HERO & DELIVERY FRAME

首屏先建立“项目交付”而非“产品陈列”的语境

画面选择的是建筑与垂直交通系统的空间关系，而不是孤立的电梯产品。它让机场、地铁与大型公共建筑的决策者在进入细节前，先感知项目规模和工程属性。

  • A深蓝底与大面积建筑照片，制造严谨、稳定的工程第一印象。
  • B主文案压缩为全球研发、制造、物流、安装、调试、服务六个动作。
  • C首个入口指向能力与项目参考，避免让访客先掉进冗长的企业介绍。
02 / INFORMATION ARCHITECTURE

把制造能力从宣传语，转成采购能核对的信息

制造模块不使用一段泛泛的“工厂实力”文字，而是把基地分布、产能、数字化质量管理和供应链能力置于同一阅读单元。采购方能在一次浏览中完成规模、地点与供给能力的初步判断。

信息层级总体承诺 → 地图证据 → 基地数据 → 工艺能力
阅读节奏先看全局，再用网格读关键数字，降低密集英文内容的理解负担
03 / INSTALLATION AS PROOF

安装项目不是幕后流程，要成为客户能看见的能力

现场施工大图承担真实感，叠加在图上的不是营销口号，而是项目负责人真正关心的四件事：谁来执行、如何控制节点、怎样保证质量、怎样保证安全。这样“安装”从一行服务清单，变成可以被信任的交付系统。

  • 01用现场图替代产品渲染，把能力放回真实工程环境。
  • 02四项控制点采用同一横向网格，便于在长页中快速扫读。
  • 03深色遮罩保证文字可读，同时让照片保留足够的工地细节。
04 / PROJECT REFERENCES

用项目分类与设备数量，证明“我做过”

项目参考并不按国家名单堆砌。我们先按机场、轨道交通、公共建筑等使用场景切分，再让每张卡片同时呈现项目名称、所在国家与设备数量。对客户来说，这是把案例库变成相似项目检索器。

分类逻辑按建筑与交通场景，而非内部部门或产品型号分类
可信信息国家、项目名、设备数量和项目现场图同时出现

SEO by design · SEO 从结构开始

可见的设计之外，网站还有一层搜索引擎能读懂的结构

这不是在上线后补几个关键词。内容、代码和图片在开发时即按索引、分享和项目询盘的实际场景组织。

01

页面语义与元数据

为页面配置独立标题、描述、canonical、Open Graph 与 Twitter 卡片，让搜索结果和对外分享都有清晰的一致表达。

02

结构化项目内容

使用 Organization、WebSite、WebPage、Service、FAQPage 与 OfferCatalog 等 JSON-LD，让服务、受众与 FAQ 有机器可读的上下文。

03

发现与性能

robots、sitemap、LLM 可读摘要和多尺寸 WebP 图片共同工作：让页面能被发现，也不牺牲跨境访问时的加载体验。
